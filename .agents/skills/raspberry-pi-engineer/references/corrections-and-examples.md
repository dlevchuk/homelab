# Виправлення, уроки та приклади

Це вибірка з прочитаних чатів, а не повна історія. Наведені репліки користувача підтверджують конкретні потреби; приклади нижче є новими ілюстраціями, а не дослівними відповідями.

## 1. Очищення залежностей зламало PWM

Джерело: чат «Підключити датчики до Raspberry Pi», `01a0c405-c244-7c80-9e7e-321405ece152`. Після поради видалити `python3-lgpio` користувач показав fallback gpiozero та `PinPWMUnsupported` на GPIO18. Асистент визнав, що пакет потрібний бузеру.

Правило: перед видаленням тестових залежностей перевір усіх споживачів, включно з другим пристроєм. Для поточного SPI BME280 зберігай `python3-spidev`; для PWM buzzer — `python3-gpiozero` і `python3-lgpio`. Очищення Blinka не означає видалення всього GPIO стека.

**Погано:** «BME280 працює через spidev, тому видали lgpio через apt autoremove».

**Добре:** «Blinka більше не потрібна BME280; lgpio залишаємо, бо gpiozero використовує його для PWM бузера. Перевіримо обидва пристрої після очищення».

## 2. Актуальна розводка й залежності мають потрапляти в проєкт

Той самий чат: користувач уточнив SPI піни BME280, а згодом попросив оновити pinout для підключених BME280 і бузера, документацію, залежності та блок показань над Host System.

Правило: розрізняй SPI та I²C за реальною схемою; при зміні hardware функції узгоджуй код, системні пакети, доступ systemd до груп і документацію. Не залишай перевірений hardware setup лише в чаті.

**Погано:** запропонувати `i2cdetect` як перевірку поточного SPI BME280 або встановити Blinka без потреби.

**Добре:** перевірити SPI0/CE0, доступ до `spidev`, chip ID; показати фізичні піни поруч із BCM, оновити роль і документований pinout.

## 3. Dashboard міграція має зберігати сервіси та вхідні посилання

Джерело: «Знайти заміну Homepage для Pi 5», `01a1e0d7-0a2f-7703-bf84-122680c992bb`. Користувач: «hermes зник з application» і «вhomepage на pi4 не забудь замінити посилання на pi5».

Правило: перед міграцією звір список застосунків, адрес і віджетів; після — перевір нову панель і посилання на неї з інших хостів. Зелений стиль був вибором для Glance у цій задачі, не загальною вимогою до всіх UI.

**Погано:** замінити Homepage на Glance і перенести лише частину закладок, забувши Hermes та Pi 4.

**Добре:** зберегти Hermes серед застосунків, адресу dashboard на Pi 5 і актуальне посилання в Homepage Pi 4; перевірити результат із браузера й окремо мережевий шлях dashboard контейнера.

## 4. Перевіряй інтеграцію по шарах

Джерело: «Встановити Hermes Agent через Ansible», `01a1ded0-bde0-7d91-ad4b-3bf8c2985349`. Користувач: «давай спочатку перевіримо чи все працює без гермесу», потім попросив перевірити через Hermes.

Правило: для збою personal Telegram перевір базовий client/auth, далі інтеграцію Hermes. Не оголошуй end-to-end успіх за одним прямим тестом. Старі дозволи на надсилання повідомлень не є дозволом на нові повідомлення.

**Погано:** багаторазово змінювати Hermes конфіг, не знаючи, чи авторизований Telegram client.

**Добре:** перевірити стан авторизації без розкриття секретів, потім виклик інтеграції; зовнішнє тестове повідомлення надсилати лише за чинним дорученням.

## 5. Діагностика SD: межі доказів

Джерело: «Надати доступ до діагностики Pi», `01a1e5cd-7eb8-7380-a73b-c0858c1fe47f`. Користувач уточнив «це pi5» після повідомлення про відсутність пристрою в контейнері. Подальша SSH перевірка читала карту на Pi. Це урок з діагностики, а не підтверджений дефект карти.

Правило: спершу визнач хост, `lsblk`/`findmnt`, журнали ядра, живлення й температуру. Відсутність локального `/dev/mmcblk0` нічого не доводить про Pi. Успішне повне читання не доводить надійність запису чи залишковий ресурс. Повноцінна перевірка ext4 потребує відмонтованого розділу; ремонт root FS плануй із іншим boot media. На підозрілий носій спершу збережи дані; не запускай write-mode badblocks або fsck repair на змонтованому root.

**Погано:** «У контейнері немає dmesg, діагностика Pi неможлива» або «Карта читається — вона повністю справна».

**Добре:** перевірити доступ із inventory/SSH конфігурації, зібрати read-only докази на Pi й окремо вказати, які властивості носія не перевірені.
