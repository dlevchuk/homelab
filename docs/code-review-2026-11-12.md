# Перевірка репозиторію — 12 листопада 2026

Перевірено Ansible, workflows, Python, shell, Jinja та документацію. Статичні перевірки охоплюють також deprecated-скрипти; функціональні перевірки зосереджені на активних ролях і виправлених помилках. Деплой, перезавантаження, перемикання Wi-Fi, надсилання повідомлень і зовнішні API не запускалися. Це не гарантує відсутності інших помилок або сумісності всіх Docker images із пристроями.

## Виправлено

- **Wi-Fi:** читання стану і назви підключення через `nmcli -g` замість виводу з назвами полів. Попередній код не розпізнавав активне клієнтське підключення та міг перейти до повторних підключень/hotspot.
- **Wi-Fi:** нуль клієнтів AP тепер повертається одним числом; раніше `grep -c ... || echo 0` повертав два нулі, що ламало числове порівняння.
- **Wi-Fi:** shell-екранування пароля, SSID та інших параметрів; пошук профілів за UUID, щоб двокрапка в назві не ламала розбір; сканування конкретного інтерфейсу; стабільна локаль; AP-профіль використовує 2.4 GHz, як і його резервне створення у скрипті.
- **Backup:** якщо `docker start` завершується помилкою, список зупинених контейнерів зберігається для повторної спроби. Обробник помилок не рекурсивно викликає себе; env-файл правильно екранує shell-значення.
- **Ping watchdog:** відновлення доступності шлюзу скидає лічильник збоїв. Окремі збої, розділені справною локальною мережею, більше не накопичуються до перезавантаження.
- **Thermal dashboard:** невдале отримання графіка не записує нуль відключень поверх добових даних; API повертає `ok: false`. SQLite-з'єднання закриваються після кожної операції, зокрема при помилці.
- **Power alerts:** помилка отримання сторінки відрізняється від порожнього графіка; вже розпочаті та минулі періоди не переносяться автоматично на завтра; назва локації екранується для Telegram HTML; ScraperAPI використовує HTTPS.
- **WSL:** apt запускається з підвищенням прав; `pexpect` встановлюється системним пакетом замість глобального pip, що несумісний із externally-managed Python у сучасному Debian/Ubuntu.
- **CI:** деплої Raspberry виконуються послідовно, щоб паралельні запуски не змінювали один Pi одночасно.
- **Документація:** опис logout-банера, поведінка без Wi-Fi secrets, фактичний шестиденний інтервал backup, умова атомарного переміщення архіву, назва змінної checksum Windows ISO, приклад shell env-файла та стан історичного IMDb backup.
- Прибрано зайві гілки Wi-Fi Netplan/networkd і standalone wpa_supplicant; для Pi 4/5 залишено NetworkManager. Це не видаляє Netplan чи wpa_supplicant із пристроїв.
- Додано `.gitignore` для локальних середовищ, Python cache і `.env`. Уже tracked-файли він не прибирає.

## Залишені питання

1. **Секрети за замовчуванням.** Portainer має відомий fallback admin password у defaults; optional FreshRSS має статичні паролі. Перед новим встановленням варто вимагати секрет замість fallback. Зміна зараз може заблокувати існуючий процес деплою, тому у цьому наборі не внесена.
2. **Вимкнення Docker-сервісів — виправлено після перевірки.** Спільна задача видаляє role-managed контейнери вимкнених сервісів, зберігаючи дані та volumes. Сторонні контейнери не зачіпаються. Beszel agent зберігає попередню умову: працює, якщо ввімкнено hub або agent.
3. **Forced restore.** Зупиняє всі активні контейнери, але подальші задачі запускають тільки сервіси, увімкнені в Ansible. Сторонні контейнери можуть залишитися зупиненими. Звичайний restore свіжої системи цього не зачіпає.
4. **Backup на різних файлових системах.** Переміщення з `/var/tmp` в Syncthing атомарне лише на одній файловій системі. Для окремого диска потрібне staging-копіювання в цільовій файловій системі з фінальним rename. Документацію уточнено.
5. **Thermal systemd:** параметр `thermal_user` використовується задачами, але unit-файли містять `User=pi` та `/home/pi`. Поточний default працює; інший користувач потребує шаблонізації unit-файлів.
6. **Графіки відключень:** парсери припускають поточну київську дату; дата графіка на сторінці явно не перевіряється. Зміна HTML або графік на завтра можуть дати неправильний день. Формат відповідей і доступність зовнішніх сервісів наживо не перевірялися.
7. **Історичний IMDb JSON:** `scripts/deprecated/backup_imdb_web/imdb_backup.json` містить прогрес scraper перед JSON і не парситься стандартним JSON parser. Оригінал збережено, щоб не змінювати історичні дані. Інші два JSON розбираються.
8. **Thermal HTTP API:** керування, видалення записів і reboot/shutdown доступні GET-запитами без власної автентифікації; код слухає всі інтерфейси. Потрібне окреме рішення про доступ (лише довірена мережа/Tailscale або автентифікація). Зовнішній доступ і firewall не перевірялися.
9. **Неперевірене середовище:** AHK/CMD не виконувалися на Windows; Docker images, SPI/камера, Wi-Fi AP та відновлення архіву не тестувалися на реальному залізі. `shellcheck` і `actionlint` локально відсутні; Bash syntax check і YAML parsing не замінюють їх.
